# 科研知识库工作流与 Obsidian 必会操作

[[Dashboard|返回科研首页]] · [[80_Guides/Obsidian与Zotero使用指南|Zotero 联动说明]] · [[90_Templates/模板索引|模板索引]]

本手册的目标不是把所有资料搬进 Obsidian，而是让每次阅读都能留下可追溯的理解，并能从研究问题找到依据、方法、实验和结论。

## 一、先分清三个工具

| 工具 | 负责什么 | 内容放在哪里 |
| --- | --- | --- |
| Zotero | 文献条目、PDF、原文批注、引用键、参考文献导出 | Zotero 文献库和附件 |
| Obsidian | 个人理解、概念、研究问题、项目计划、实验记录和 Markdown 链接 | 本知识库 |
| GitHub | 笔记的版本历史和仓库备份 | `Chisato-reco/obsidian_chaofen` |

Zotero 标注被导入，只代表摘录有了可搜索的落脚点；**知识卡片应写自己的解释、出处、适用条件和与课题的联系。** Zotero 文献同步、Obsidian 笔记同步、PDF 附件同步是三件独立的事。

## 二、一次完整的文献到实验流程

### 1. 收集与筛选

1. 在 Zotero Connector 保存论文，确认标题、作者、年份、DOI 和 PDF 没有错。
2. 将论文放入 Zotero 的课题分类，例如“电镜超分 / 退化建模”或“电镜超分 / 重建方法”；分类可多选，不要靠目录名承载所有信息。
3. 确认 Better BibTeX 已给论文分配 citekey。citekey 是稳定机器标识，用于导入文件名和引用；**不要为了好看频繁修改**。
4. 快速筛选时，只写这篇论文与哪个研究问题有关，以及是否值得精读。无需每篇都做长笔记。

### 2. 在 Zotero 阅读和标注

在 PDF 里围绕证据做少量、有目的的批注：

| 颜色 | 本库约定 | 适合标什么 |
| --- | --- | --- |
| 黄 | 背景与概念 | 问题定义、关键事实、必要理论 |
| 绿 | 方法与创新 | 模型、算法、实验设计、贡献 |
| 蓝 | 结果与证据 | 定量结果、图表、对照实验 |
| 红 | 局限与疑问 | 假设限制、失败条件、未解决问题 |

在 Zotero 的批注 comment 写自己的短问题，例如“这项结论是否只对晶体样品成立？”把**原文摘录**和**自己的判断**分开。要引用图表时用区域批注，并记下图号及它支持的结论。

英文阅读时可用已安装的 Translate for Zotero 查词、查看音标或选段翻译。把关键术语的语境义和来源页码写入个人笔记；具体操作见 [[80_Guides/Zotero科研英语查词与翻译|科研英语查词指南]]。

### 3. 导入 Obsidian 文献笔记

1. 保持 Zotero 运行，在 Obsidian 按 `Ctrl+P`，运行 **Zotero Integration: Create Literature Note**。
2. 搜索标题或作者，选择论文的父条目，生成 `10_Literature/<citekey>.md`。
3. 检查摘要、期刊、年份、DOI、PDF 和批注链接；点“查看原文”确认能回到 Zotero PDF 对应页。
4. 在“阅读总结”保留区完成下一节的五问。只需重读时才补充批注；不用把整篇文章搬进笔记。
5. 更新 Zotero 标注后重新导入。模板会刷新自动生成部分；自己的文字只写在 `research-summary` 或 `notes` 保留区。不要删掉 `%% begin ... %%`、`%% end ... %%` 和末尾 Import Date 标记。旧笔记若没有这些标记，先备份并按[[80_Guides/Obsidian与Zotero使用指南#更新批注与保护笔记|更新批注与保护笔记]]处理，再导入；不能仅凭“阅读总结”标题判断文字已受保护。

### 4. 把论文变成自己的知识

每篇值得精读的论文，至少回答：

1. **问题**：作者要解决什么问题？为什么已有方法不够？
2. **方法**：核心假设、数据、模型或算法分别是什么？
3. **证据**：哪张图、哪张表或哪组对照支持结论？是否有反例或边界？
4. **迁移**：它对电镜超分有什么启发？数据条件、噪声、成像物理和评价指标是否相同？
5. **下一步**：提出一个可检验的问题，而不是直接把“可以尝试”当作结论。

当一个术语或方法在多篇论文、项目和实验中反复出现时，再建立一篇 `40_Knowledge` 知识卡片。卡片写定义、直觉、适用条件、常见误用、证据来源，并链接到相关论文。若只是单篇论文中的背景介绍，留在文献笔记里即可。

### 5. 从知识回到研究任务

在 [[20_Projects/电镜超分/项目总览|项目总览]] 维护少量当前问题和下一步任务。每个待办尽可能写成可检查动作，例如：

> 对同一批留出图像比较 bicubic 与实测 PSF 退化，记录 PSNR、SSIM 和 FRC；确认两种退化设置及数据划分后再决定训练基线。

任务引用依据论文、概念卡片或已有实验。不要把多个方向塞进一条巨大待办；一条只对应一个明确结果。

### 6. 计划、运行并记录实验

1. **运行前**：在项目页写实验方案，包含假设、相对基线的唯一改动、数据版本/划分、环境、代码 commit、配置和随机种子；开始实际执行时，用实验模板在 `30_Experiments` 建记录。
2. **运行中**：记录实际命令、失败、重试和异常，不只记最终最好的一次。
3. **运行后**：把 PSNR、SSIM、FRC 等与评价实现、单位、数据条件一起记录；贴日志、输出或图表路径。
4. **得出结论**：说明证据支持什么、还不能说明什么、可能混杂因素是什么，并链接回项目问题和相关论文。
5. 不要把模板里的示例数字当实际结果；新模板使用“待测”，只填真正运行过的数据。

### 7. 每周回顾与维护

- 清理 `00_Inbox`：归档、建立链接或删除重复临时内容。
- 项目页只保留当前目标、阻塞点和下一步；完成项移入对应实验或阶段总结。
- 从实验结果反向检查：是否需要新概念卡片、补读论文或修正假设？
- 检查 GitHub 同步成功。Git 备份笔记，不替代 Zotero 文献和 PDF 的同步。

## 三、Obsidian 必会操作

### 1. 双链：知识网络的基本语法

在编辑器输入 `[[` 搜索并选择现有笔记。推荐用显示文字，让链接对人可读：

```markdown
[[40_Knowledge/电镜超分辨率基础与FRC评价|电镜超分基础与评价卡片]]
[[10_Literature/chenElectronPtychographyAchieves2021|Chen 等（2021）]]
[[20_Projects/电镜超分/项目总览#3. 技术路线与关键模块|项目技术路线]]
[[40_Knowledge/电镜超分辨率基础与FRC评价#1. 傅里叶环相关 (Fourier Ring Correlation, FRC)|定位到 FRC 小节]]
```

`[[路径]]` 指向整篇笔记，`#` 后写目标标题的完整文字，`|` 后写此处显示文字。路径从知识库根目录算起，即使在 Windows 也用 `/`。输入目标文件后再键入 `#`，从候选标题中选取，避免漏掉编号、空格或标点。设置 → 文件与链接 → 自动更新内部链接，可在重命名文件时更新库内链接；改标题或块 ID 后仍应检查引用。[官方：内部链接](https://help.obsidian.md/links)

#### 块 ID：精确引用一段话

以下是真实段落，行尾已经有可用的块 ID（在源码模式可见）：

每次阅读结束，留下一条有出处的理解或一个明确的待解问题；尚未核实的内容标为待验证。 ^workflow-reading-check

可复制的原始写法如下。复制到其他笔记时使用该笔记内唯一的 ID，不要在同一笔记重复定义它：

```markdown
每次阅读结束，留下一条有出处的理解或一个明确的待解问题；尚未核实的内容标为待验证。 ^workflow-reading-check
```

下面两行分别“跳转到段落”和“把段落内容嵌入当前位置”，都指向本指南中已有的段落：

```markdown
[[80_Guides/科研知识库工作流与Obsidian必会操作#^workflow-reading-check|阅读收尾标准]]
![[80_Guides/科研知识库工作流与Obsidian必会操作#^workflow-reading-check]]
```

点击验证：[[80_Guides/科研知识库工作流与Obsidian必会操作#^workflow-reading-check|阅读收尾标准]]。块 ID 只用英文字母、数字和连字符；普通段落在行尾加空格后写 `^ID`。列表、表格或引用整体的 ID 要另起一行，并在前后留空行。输入目标文件后的 `#^` 可选已有块。块引用属于 Obsidian 扩展语法，其他 Markdown 工具未必支持。[官方：块链接](https://help.obsidian.md/links#Link%20to%20a%20block%20in%20a%20note)

#### aliases 与显示文字有什么区别

- `[[真实路径|显示文字]]`：只改变这一处链接的外观，不改文件名，也不为目标笔记增加别名。
- `aliases`：目标笔记的属性，登记可复用的别名，用于按别名查找、补全链接及发现未链接提及；不等于自动建立链接。

例如，库内 Chen 文献已有如下别名。这里只展示现有属性；手动添加时应合并到文件开头已有的属性区，不要新建第二个属性区或覆盖其他字段：

```yaml
aliases:
  - "Chen 2021｜电子叠层成像与原子分辨率"
```

输入 `[[Chen 2021` 并选中候选后，链接仍以真实笔记为目标，例如 `[[10_Literature/chenElectronPtychographyAchieves2021|Chen 2021｜电子叠层成像与原子分辨率]]`（自动生成的路径长短取决于链接设置）。临时简称直接用 `|`；经常使用的名称才登记到 `aliases`，不要靠手写 `[[别名]]` 代替明确目标。[官方：别名](https://help.obsidian.md/aliases)

优先链接有后续价值的**概念、问题、方法、论文和实验**。不必给每个普通词都加链接；只有真正能从上下文跳过去并继续工作的链接才有用。

### 2. 出链、反向链接与关系检查

- **出链**：当前笔记引用了什么。文献页应链接相关概念和项目；实验页应链接研究问题、方法和依据。
- **反向链接**：哪些笔记链接到了当前笔记。查看某个方法卡片的反向链接，再读上下文，判断引用属于定义、质疑、计划还是实际使用；有链接不等于用过或支持它。
- **未链接提及**：Obsidian 发现了同名词但尚未建立链接时，可判断是否值得连接。相同术语不一定表示相同概念，先看上下文。

先在设置 → 核心插件启用“出链”“反向链接”。打开右侧相应面板；看不到反链时，用 `Ctrl+P` 搜索 **Backlinks: Show backlinks**（中文界面可搜“反向链接”）。选中哪篇笔记，面板就显示它的反链。[官方：反向链接](https://help.obsidian.md/plugins/backlinks)

#### 让关系有含义，而不只是凑链接

每条链接前后写清“为什么连接”。用本库现有页面走通下列路线，但不把它当成已得到的科研结论：

| 节点与入口 | 应写明的关系 | 下一步去哪里 |
| --- | --- | --- |
| [[20_Projects/电镜超分/项目总览#4. 近期任务清单 (TODO)|项目任务]] | 这个问题需要查什么依据或验证什么条件？ | 文献或概念卡片 |
| [[10_Literature/chenElectronPtychographyAchieves2021#阅读总结|Chen 文献阅读总结]] | 作者讨论了什么？依据在哪页、哪张图？与当前问题是否有关？ | 仅在读过后链接实际涉及的概念；无关就不连 |
| [[40_Knowledge/电镜超分辨率基础与FRC评价#2. 电镜超分核心难点与网络设计要点|现有概念卡片]] | 概念如何帮助界定项目问题？哪部分是来源内容，哪部分是个人假设？ | 返回项目页写待验证方案 |
| [[30_Experiments/实验目录|实验记录入口]] | 实际采用了什么方案，结果支持或不支持哪个项目假设？ | 真实运行记录 → 项目下一步 |

这张表是导航与记录要求，不表示 Chen 论文已经为该卡片的 FRC 内容提供证据。完整链条应是“项目问题 → 文献依据 → 概念及适用条件 → 实验检验 → 项目决策”，方向也可反过来追溯。尚无真实实验时，停在项目方案；[[95_Examples/20261106-Baseline-Init|预置 Baseline 记录]]只用于看格式，其数字与完成状态不能充当实测结果。

### 3. 搜索与快速切换

- `Ctrl+O` 快速切换笔记：按文件名或别名找笔记；要找正文中的作者、术语或实验命令，用全库搜索。
- `Ctrl+Shift+F` 全库搜索：找术语、citekey、实验命令或 DOI；必要时限制路径或标签。
- `Ctrl+P` 命令面板：搜索创建文献笔记、插入模板、切换阅读视图等命令；插件命令需对应插件已启用。
- 查找 Zotero 原文：在全库搜索 citekey 或 DOI，再从文献笔记的 Zotero / PDF 链接打开原文。

以上为 Windows 默认快捷键；可在设置 → 快捷键核对本机绑定。快速切换、搜索和命令面板均为核心插件。官方说明：[快速切换](https://help.obsidian.md/plugins/quick-switcher)、[命令面板](https://help.obsidian.md/plugins/command-palette)、[快捷键设置](https://help.obsidian.md/hotkeys)。

在 `Ctrl+Shift+F` 搜索框中直接复制以下查询（不带反引号）：

| 查询 | 用途 |
| --- | --- |
| `path:"10_Literature/" "ptychography"` | 只在文献目录中查术语 |
| `file:chenElectronPtychographyAchieves2021` | 按文件名找当前 Chen 文献 |
| `"Fourier Ring Correlation"` | 按完整短语搜索 |
| `path:"20_Projects/" task-todo:基准` | 找项目中包含“基准”的未完成任务 |
| `path:"30_Experiments/" (PSNR OR SSIM)` | 找实验记录中含任一指标的笔记；没有记录可为空 |
| `tag:#knowledge` | 找实际带有 knowledge 标签的笔记 |
| `[citekey:chenElectronPtychographyAchieves2021]` | 按属性值查文献 |
| `FRC -path:"95_Examples/" -path:"80_Guides/"` | 排除示例和指南，查其余笔记 |
| `line:(数据 划分)` | 要求两个词在同一行出现 |

空格连接表示同时满足，`OR` 表示任一，`-` 表示排除，括号控制组合；`path:` 查路径，`file:` 查文件名。零结果不一定是故障，可能尚无符合内容。复杂查询可打开搜索的“解释搜索词”检查解析；排除文件设置也会影响结果。[官方：搜索语法](https://help.obsidian.md/plugins/search)

### 4. 属性和标签：结构化筛选

**属性**放少数稳定字段，例如 `citekey`、`year`、`status`、`model_type`、`dataset`。用于排序、筛选和 Dataview。值尽量统一：年份用数字，日期用 ISO 格式；状态选一套固定词汇。

**标签**用于横跨文件夹的主题或工作状态，例如 `#literature/review`、`#method/degradation`、`#status/to-read`。先从现有词汇选，避免同义标签并存，例如“超分”“超分辨率”“SR”三套都用。文件夹回答“这是什么类型的记录”，标签回答“它属于哪些横切主题”；不要复制一整套目录层级做标签。

不确定是否需要新标签时先加双链。双链能指向一篇有定义、说明和关系的中心笔记；标签只是筛选词。

### 5. 模板、属性视图与 Dataview

- 用 [[90_Templates/模板索引|模板索引]]选择文献、实验或概念模板。
- Zotero 文献模板由 Zotero Integration 读取，**不要用 Templater 插入或渲染它**。
- Templater 用于手动新建实验、概念或速读笔记，并填入日期等动态字段。
- Dataview 可用统一属性自动生成文献、实验和概念清单。若表格为空，先核对笔记的 frontmatter 属性名称和所在目录，再检查 Dataview 插件是否启用。
- 如果只是轻量浏览，可以用 Obsidian 核心属性视图或 Bases；不要为了仪表盘给每篇笔记增加大量没人维护的字段。

### 6. 折叠、嵌入与图表

- 点击标题左侧箭头折叠大纲；摘要、长引用、原始批注适合折叠，自己的结论应直接可见。
- `![[20_Projects/电镜超分/项目总览#4. 近期任务清单 (TODO)]]` 嵌入现有任务章节；源笔记修改后，嵌入随之更新。块嵌入示例见上文。嵌入是展示源内容，不是另存一份。[官方：嵌入文件](https://help.obsidian.md/embeds)
- 图像先保存到库内附件目录，再输入 `![[` 选择实际存在的图片文件（保留扩展名）；旁边写来源、图号和观察。不要复制不存在的示例图片路径。
- Canvas 适合少数需要空间布局的复杂问题，如“退化因素→算法→评价指标”路线图；Canvas 不替代可搜索的普通 Markdown 笔记。
- Graph View 用来发现连接稀疏或孤立的笔记，不是知识质量指标。笔记很多但链接没有明确含义，图谱也不会自动形成知识体系。

### 7. 阅读模式与修改

- **阅读视图 ↔ 编辑视图**：Windows 默认 `Ctrl+E`，或使用右上角视图按钮。编辑视图分“实时预览”和“源码模式”；检查 YAML、块 ID、导入保护标记时用源码模式。两种编辑模式可用命令 **Toggle Live Preview/Source mode** 切换，快捷键以本机设置为准。[官方：视图与编辑模式](https://help.obsidian.md/edit-and-read)
- **页面预览**：启用设置 → 核心插件 → 页面预览（Page preview）。阅读视图悬停在内部链接上预览；编辑视图默认按住 `Ctrl` 再悬停。是否要求 Ctrl 可按使用场景在该插件设置调整。普通未链接词语不会因此出现页面预览。[官方：页面预览](https://help.obsidian.md/plugins/page-preview)
- **打开链接**：阅读视图点击内部链接；编辑视图可按住 `Ctrl` 点击。预览、打开链接和词典查词是不同操作；词典以相应插件说明为准。

文件列表用于分类浏览，快速切换和搜索用于日常定位。常用首页、文献目录、项目总览和实验目录可加入书签；无需先掌握图谱或复杂看板。

## 四、建议掌握顺序

先掌握这些基础操作，再逐步扩展：

1. **先会找与看**：`Ctrl+O`、`Ctrl+Shift+F`、`Ctrl+P`、`Ctrl+E`；能找回一篇笔记并切换源码模式。
2. **再会关联**：整篇链接、完整标题链接、显示文字与反链；能解释一条链接的关系。随后练块 ID、嵌入和 aliases。
3. **跑通阅读闭环**：导入一篇文献、跳回原文，并亲手写“问题—方法—证据—迁移—下一步”；暂时答不出的写待核实。
4. **按需抽取概念**：确有可复用内容时才建卡，标明实际来源与边界。一篇可靠来源也可起步，不要求凑两篇；之后再补充或修正。
5. **连接实际行动**：项目中写可检查任务，实际运行后记录实验，并链接回问题与依据。
6. **最后优化管理**：统一少量属性和标签，按需用 Dataview 或 Bases；每周检查待办与备份状态。

核心验收不是图谱有多少节点，而是随机打开一个研究问题时，能沿链接找到相关论文和页码、知识概念、实验条件与结论，并能说明证据的边界。

## 五、一篇论文的精读验收单

- [ ] Zotero 条目信息和 PDF 正确，citekey 稳定。
- [ ] Obsidian 笔记能跳回条目和具体批注页。
- [ ] 我能用自己的话写出问题、方法、证据与局限。
- [ ] 关键判断有论文页码、图表或实验记录作为依据。
- [ ] 文献笔记至少连接到一个研究问题或概念；如果没有实际关联，不为凑数量强行建链。
- [ ] 若形成可复用认识，已建立概念卡片并关联来源。
- [ ] 总结和个人想法写在 Zotero 再导入仍会保留的位置。

## 六、你可以立刻完成的 30 分钟练习

1. 打开 [[10_Literature/chenElectronPtychographyAchieves2021|Chen 等（2021）文献笔记]]，从一个批注链接回 Zotero 检查页码。
2. 在“阅读总结”保留区用自己的话回答：这篇论文主要解决什么成像问题？它是否直接研究深度学习超分？
3. 从刚才读过的内容选一个不懂的概念，写一句自己的解释和原文页码；查不到就写一个具体问题，不填想象中的结论。
4. 若确实对应现有知识卡片或[[20_Projects/电镜超分/项目总览|当前课题]]，加链接并写清关系；否则先保留在文献笔记中。
5. 打开被链接的目标笔记，查看反向链接并返回论文；没有合理目标时，改练本指南的“阅读收尾标准”块链接。

若该论文与 FRC 或当前课题并无直接证据关系，不必建立连接。自己的迁移设想应单列为待验证假设，并说明还缺什么证据。

## 七、一天与一周的执行清单

### 每天：围绕一个小问题，约 30–60 分钟

- [ ] **开始 5 分钟**：打开项目任务，只选一项今天可检查的动作，例如定位一张图的实验条件。
- [ ] **阅读 20–40 分钟**：在 Zotero 查对应段落、图表和方法；少量批注，记录页码及自己的疑问。
- [ ] **整理 10 分钟**：需要时导入或更新笔记，确认保护标记；写一条有出处的理解、适用条件或未解问题。
- [ ] **收尾 5 分钟**：给实际相关的项目、概念或实验加链接并说明关系；留下下一次可直接开始的动作。当天做了实验就补齐配置、日志路径和真实结果。
- [ ] **检查保存与备份状态**：区分本地保存、笔记备份与 Zotero 同步；本清单不要求每次执行提交或推送。

时间不足时，只完成“一个问题 + 一个出处 + 一个下一步”。不要求每天读完一篇或新建卡片。

### 每周：约 30 分钟回顾

- [ ] 清理收集箱：保留、归档或删除重复项；无须把所有摘录变成卡片。
- [ ] 核对本周关键判断是否能回到原文页码、图表或真实实验；把未经验证的判断标清楚。
- [ ] 检查一个核心概念的反链：关系是否明确，有无断链、同名误链或没有依据的关联。
- [ ] 回看实际实验的配置与结果，记录失败、限制和未解决问题；不把预置示例计入进展。
- [ ] 在项目页更新完成项、阻塞点和下周 1–3 个可检查动作；计划仍放项目页。
- [ ] 查看笔记备份与 Zotero 同步状态，有异常再按联动指南排查。
